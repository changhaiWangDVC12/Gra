自动微分（automatic differentiation, autodiff）—— 先给直觉，再给机制，最后给在 PyTorch 里怎么用、哪里会踩坑。下面所有数字我都实际跑过。

━━━━━━━━━━━━━━━━━━━━
一、先破一个误解：它既不是「数值近似」，也不是「符号推导」

求导有三条完全不同的路，很多教材混着讲，所以会晕：

  数值微分（finite difference）(人脑确实常用，但是计算机好像不是特别喜欢用
    做法：f'(x) ≈ (f(x+h) − f(x−h)) / 2h
    优点：两行代码，任何黑盒函数都能用
    缺点：是近似值，而且步长 h 极难选。我实测 f(x)=3x+sin(x) 在 x=2 处的中心差分误差：
        h = 1e-3   → 误差 +6.9e-08   （截断误差主导）
        h = 1e-6   → 误差 −2.4e-11   （刚好是最优点附近）
        h = 1e-12  → 误差 +3.0e-04   （浮点相减吃掉了有效位，灾难性抵消）
    更致命的是：n 个参数要算 n 次函数求值。100 万个参数的模型没法这么求梯度。

  符号微分（sympy 那种）
    做法：按求导规则对表达式做代数变形，得到一个新的解析表达式
    优点：结果精确，形式可观
    缺点：表达式会指数膨胀（复合函数套得越深，输出的式子越大），而且它只能处理「表达式」，处理不了程序里的 if / for / while，也处理不了「给一个输入、算一个数」的神经网络。

  自动微分
    做法：不去推导整体表达式，而是把程序拆成一连串基本运算（+ − × ÷ sin exp relu…），每个基本运算的导数规则是写死的；运行时把中间量连成一张计算图，再沿图反复用链式法则把局部导数乘起来。
    结果：数值精确到机器精度（和解析式算出来一样，不是近似），代价只是常数倍的基本运算开销，而且完全能处理 if / for —— 分支在这一次运行里走哪条路，图就长成什么样。

一句话：数值微分是「用函数值猜斜率」，符号微分是「把斜率写成一个公式」，自动微分是「用链式法则沿着计算过程把斜率传播过去」。

━━━━━━━━━━━━━━━━━━━━
二、机制：计算图 + 链式法则（这是全部内容）

拿最简单的 f(x, y) = x·y + sin(x) 举例，x=2, y=3。程序实际做的是四步：

    a = x · y          →  ∂a/∂x = y = 3,      ∂a/∂y = x = 2
    b = sin(x)         →  ∂b/∂x = cos(x) = −0.4161
    f = a + b          →  ∂f/∂a = 1,          ∂f/∂b = 1

每个箭头是一段「局部导数」，是算子自带的知识，不需要推导。剩下的就是把它们乘起来并相加：

    ∂f/∂x = ∂f/∂a · ∂a/∂x + ∂f/∂b · ∂b/∂x = 1·3 + 1·(−0.4161) = 2.5839
    ∂f/∂y = ∂f/∂a · ∂a/∂y                  = 1·2               = 2

注意 x 到 f 有两条路径（经过 a 和经过 b），这就是链式法则里那个「求和」——多路径必须全加起来，漏一条就是错的。这是手推公式最容易错的地方，而自动微分靠图的遍历自动完成。

我把这个过程写成 30 行纯 Python（不用任何库，可以粘进 Jupyter 直接跑），核心就三件事：前向存数值、记下局部导数、反向逆序遍历把梯度累加到父节点。实跑结果：

    f(2,3)  = 6.9092974268
    df/dx   = 2.5838531635    （解析值 y+cos(x) = 2.5838531635）
    df/dy   = 2.0000000000    （解析值 x       = 2.0000000000）
    数值微分对 df/dx = 2.5838531634

五件事你可以在自己机器上验证：改 x、y 的取值，自动微分的输出永远和解析式逐位一致；换成数值微分就会有上表那种误差。代码我存在服务器 /tmp/ad_demo.py，需要的话我可以给你全文。

━━━━━━━━━━━━━━━━━━━━
三、前向模式 vs 反向模式（你最该搞清的一点）

同一个链式法则，从哪头乘，得到的东西完全不同：

  前向模式（forward mode）
    从输入往输出推。每个中间量身上带的不是「梯度」，而是「本中间量对某一个输入的导数」。#实际上大方向任然是x->y
    一次前向扫 = 拿到「所有输出对某一个输入的导数」。
    要拿到完整梯度（对所有输入的），就要每个输入各扫一遍 → n 次。

  反向模式（reverse mode）    这里的方向是y->x所以称为反向模式
    先正常前向算一遍数值，再从输出往回推。每个中间量身上带的是「输出对本中间量的偏导」（叫伴随值 / adjoint）。
    一次反向扫 = 拿到「一个输出对所有输入的导数」，一次到位。

关键的对比（粗算，按每次扫描的基本算子次数 × 扫描次数计）：

    n 元输入、1 个标量输出，要拿到完整梯度：
      n = 10        前向 810 次算子     反向 81 次算子        前向贵 10 倍
      n = 100       前向 89,100        反向 891             前向贵 100 倍
      n = 1000      前向 8,991,000     反向 8,991           前向贵 1000 倍
      n = 100000    前向 9.0e10        反向 8.99e5          前向贵 100000 倍

    反过来，1 个输入、m 个输出：
      m = 100       前向 300 次        反向 30,000 次      前向便宜 100 倍

规律很干净：反向模式的成本与「输入个数」无关，前向模式的成本与「输出个数」无关。

也就是说，肯定是要使用反向模式进行训练。

于是结论就出来了：
  · 深度学习是「百万个参数 → 1 个标量损失」，输入多、输出少 → 必须用反向模式。这就是为什么 backprop 本质上就是「反向模式自动微分」这一个东西的工程实现。
  · 反过来，输入少输出多（比如一个输入要算 100 个不同指标的敏感度，或者要求雅可比的一整列）→ 前向模式更划算。
  · 术语对照：前向模式算的是 JVP（Jacobian-Vector Product，雅可比矩阵乘一个向量，一次一列）；反向模式算的是 VJP（Vector-Jacobian Product，一次一行）。PyTorch 的 backward 是 VJP，JAX 的 jvp/vjp 两个都给你。

━━━━━━━━━━━━━━━━━━━━
四、落到 PyTorch：语法背后的图

    x = torch.randn(3, requires_grad=True)   # 标记为叶子张量，要求梯度
    w = torch.randn(3, 3, requires_grad=True)
    y = (w @ x).sin().sum()                  # 前向：每步都记下 grad_fn（图节点）
    y.backward()                             # 反向：从 y 出发遍历图
    print(x.grad, w.grad)                    # 梯度写回叶子张量的 .grad

你看到 y.grad_fn 那串（SinBackward0 → SumBackward0 …）就是计算图本身。五个必须知道的坑：

  1) 梯度是「累加」不是「覆盖」。backward() 一次就往 .grad 上加一次。所以每个训练步之前要
       optimizer.zero_grad()   或   optimizer.zero_grad(set_to_none=True)
     忘了它，第 100 步的梯度是前 99 步的和 —— 典型的「loss 不降、梯度越来越大」。
     这个设计本身有用：想手动累积 4 个小 batch 再更新一次，就不要清零，这叫梯度累积。

  2) 默认只有叶子张量保留 .grad，中间量为了省显存不保存。要看中间量就 x.retain_grad()，或者用 torch.autograd.grad(y, x) 直接要某一个的梯度（它不写 .grad）。

  3) 推理要包在 with torch.no_grad(): 里。否则验证/测试时也在建图、也在存激活，显存白涨一大截。评估循环里忘了这个是很常见的显存泄漏来源。

  4) .detach() 用来断图：把某个张量从计算图里摘出来（比如 target、或者强化学习里的旧策略输出）。断错了位置，梯度就流不到该到的地方，表现是「参数不动」。与之相对，想原地改一个 requires_grad 的张量，要在 with torch.no_grad(): 里改，否则报 "a leaf Variable that requires grad is being used in an in-place operation"。

  5) 反向图默认用完就释放。想连着 backward 两次（比如要二阶导、或者 GAN 里要分别对两个网络反向），要 retain_graph=True；要二阶导还得先 y.backward(create_graph=True)。

还有一个「代价」层面的事实值得记住：自动微分把计算换成了内存。前向时每个操作的中间结果都要留着给反向用，所以显存开销大致随网络深度线性增长，而计算量和一次前向同阶。整个「梯度检查点（gradient checkpointing）」技术就是在跟这件事做交易：不存中间激活，反向时重算一遍，用时间换显存。


如果只记三句话

  1. 自动微分 = 把程序拆成基本算子，每个算子自带局部导数，运行时沿计算图用链式法则乘起来（多路径要相加）。结果精确，不是近似。
  2. 反向模式一次就能算出「一个标量对所有输入的梯度」，成本与输入个数无关 —— 所以深度学习用它，backprop 就是它的工程名字。
  3. 在 PyTorch 里的全部实践要点就是：zero_grad、no_grad、detach 这三个词用对，梯度就不会错。

















2.5.2非标量变量的反向传播
一、先把那两句「矩阵 / 高阶张量」翻译成人话

  当 y 和 x 都是向量时，导数确实是一张矩阵（雅可比矩阵 J，J[i][j] = ∂y_i/∂x_j）；
  再往高阶、高维走，就是更高阶的张量。

  但这只是「数学上更自然的写法」，不是「工程上要算的东西」。原因很实际：

    · 一个 batch 有 B 个样本、网络有 P 个参数时，雅可比是 B×P 的矩阵；
      而 P 动辄百万、B 动辄几百 —— 这张矩阵根本存不下，也根本没人要。

  所以那段话的落点是最后一句：我们的目的不是算微分矩阵，而是「单独计算批量中每个样本的偏导数之和」——
  也就是把 B×P 的矩阵压成 1×P 的一行。这一行就是梯度。

二、那为什么 y 是标量时不用传参数、是向量时就要传？

  因为对向量求导有太多「可能的意思」（整张矩阵？哪一行？加权和？），PyTorch 不猜。它的实际算术是这样：
  backward() 算的是「一个标量对 x 的梯度」，而向量 y 不是标量，于是它直接报错。我实跑的原文：

    RuntimeError: grad can be implicitly created only for scalar outputs
    （中文：梯度只能对「标量输出」隐式创建）

  你传进去的那个向量，就是替它把 y 压成标量用的权重。

三、传进去的 v 到底是什么（这是全篇的关键）

    y.backward(v)  等价于  (v · y).backward()

  其中 v·y 是点积 —— 一个标量。也就是说：

    backward(v) 算的是  vᵀ J
    数学名字叫 VJP（Vector-Jacobian Product，向量乘雅可比）

  它等于「把 y 的每一行按 v 的权重加起来，再对 x 求导」。
  传全 1，就是「每条输出同等权重地加起来」= 求和。
  传 [1, 1, 1, 10]，就是「第 4 条输出的权重是 10 倍」。

  所以书里那句注释「本例只想求偏导数的和，所以传递一个 1 的梯度是合适的」，
  不是「随便填个 1 凑数」，而是「1 = 每个样本等权相加」。

四、三个实测输出（x = [0,1,2,3]，y = x·x，所以 ∂y_i/∂x_i = 2x_i）

    y.sum().backward()                     -> x.grad = [0.0, 2.0, 4.0, 6.0]
    y.backward(torch.ones(len(x)))         -> x.grad = [0.0, 2.0, 4.0, 6.0]      ← 完全一致
    y.backward([1., 1., 1., 10.])          -> x.grad = [0.0, 2.0, 4.0, 60.0]     ← 最后一条被放大 10 倍

  手工核对：grad_i = 2·x_i·v_i，v=[1,1,1,10] 时是 [0, 2, 4, 60]，逐位吻合。

五、为什么真实训练里「求和」就是对的

  一个 batch 的损失本来就是「每个样本损失的总和」：

    L = ℓ₁ + ℓ₂ + ... + ℓ_B

  反向传播要的是 ∂L/∂w = Σᵢ ∂ℓᵢ/∂w，这正是「对 per-sample loss 组成的向量传一个全 1 的梯度」。

  实跑验证（3 个样本，loss_i = (x_i·w − t_i)²，w=2 → per-sample loss = [1, 4, 9]）：

    loss = sum(...)   → loss = 14.0000    w.grad = 28.0000
    loss = mean(...)  → loss =  4.6667    w.grad =  9.3333
    手工核对 sum  = 28.0        mean = 28/3 = 9.3333   ✓

  这里顺带一个实践提醒：书里用 sum（看的是概念），真实训练通常用 mean，因为
  用 sum 的话，梯度大小和 batch size 成正比 —— 你把 batch 从 8 改成 64，等于把学习率乘了 8 倍。

六、如果真的要点那张矩阵怎么办

  一次 backward 只能拿一行（一个 VJP），所以想要整张雅可比得循环逐行求：

    for i in range(len(x)):
        J.append(torch.autograd.grad(y[i], x, retain_graph=True)[0])

  我实跑出来就是对角阵 diag(0, 2, 4, 6) —— 因为 y = x·x 是逐元素运算。
  更省事的做法是用 functorch 的 jacrev/jacfwd，但对训练来说基本用不到：
  loss 本身已经是标量了。

七、一句话总结

  y 是向量 → 不能说「算它的梯度」，只能指定一个权重向量 v，让 PyTorch 算 vᵀJ；
  传全 1 → 就是「对所有样本的偏导求和」，也就是我们真正要的 batch 梯度；
  y.sum().backward() 只是 y.backward(torch.ones(...)) 的写法糖。

零、先看这段程序在干什么

    def f(a):
        b = a * 2
        while b.norm() < 1000:      # |b| 还小，就一直翻倍
            b = b * 2
        if b.sum() > 0:             # 正的就直接返回
            c = b
        else:                       # 负的再乘 100
            c = 100 * b
        return c

    a = torch.randn(size=(), requires_grad=True)   # 一个随机标量
    d = f(a)
    d.backward()

打印出来的结果是 a.grad == d / a（书的结论）。要理解为什么，先把"这一次运行到底走了哪条路"打印出来看。

━━━━━━━━━━━━━━━━━━━━
一、把行程表打印出来（同一段代码，四次完全不同的旅程）

我给 f 装了一个"行程表"，把每一步的 b 都打出来：

    a = 0.1    → b: 0.2 → 0.4 → 0.8 → ... → 819.2 → 1638.4（循环 13 次）→ 分支取 b      → f = 1638.4
    a = 1.0    → b: 2 → 4 → ... → 512 → 1024（循环 9 次）      → 分支取 b      → f = 1024
    a = -1.0   → b: -2 → -4 → ... → -512 → -1024（循环 9 次）  → 分支取 100*b  → f = -102400
    a = 100.0  → b: 200 → 400 → 800 → 1600（循环 3 次）        → 分支取 b      → f = 1600

四件事一眼可见：

  · 循环次数从 3 变到 13，完全由 |a| 决定（|b| 什么时候超过 1000，就停）
  · 走哪个分支由符号决定（a>0 走 c=b，a<0 走 c=100b）
  · 所以这四次运行画出来的是四张结构不同的计算图：一个 5 层、一个 11 层、一个 15 层
  · 但它们有一个共同点 —— 下面第二点

━━━━━━━━━━━━━━━━━━━━
二、最关键的一步：为什么 f(a) 永远是 k·a

先手推 a = 0.1 这一路：

    b = a*2            → 2a
    while 第 1 轮        → 4a
    while 第 2 轮        → 8a
    ...
    while 第 13 轮       → 2¹⁴ a = 16384a = 1638.4     （因为 0.1×16384 = 1638.4 ✓）
    c = b              → f = 16384a

也就是说：这次运行里，f(a) = 16384·a。那 16384 是什么？就是这一路乘上去的那一串常数的乘积：2 × 2 × 2 × ... = 2¹⁴。

再手推 a = −1 这一路：

    b = −2 → −4 → … → −1024            （10 次乘 2，所以是 2¹⁰ a）
    c = 100 * b = 100 · 2¹⁰ · a = 102400 a

a = 100 那一路：2⁴ a = 16a。a = −42 那一路：100 · 2⁵ = 3200（乘 3200 倍）。

所以规律是：

    无论走哪条路，f(a) 都是「某个常数 k 乘 a」的形式，
    k 由「这次运行乘了几次 2、有没有乘 100」决定 → k = 2^m 或 100·2^m

而一个形如 f(a) = k·a 的函数，导数就是 k（就是一条过原点的直线，斜率是 k）。于是：

    a.grad = k
    d / a  = (k·a) / a = k
    ⟹ a.grad == d / a

这就是书中那句结论的全部来历 —— 它不是什么新公式，而是「这个特定的 f 恰好是线性的（分段线性）」。

对照实测表（每一行都是同一个 k 的三种算法）：

        a      循环次数     k=f(a)/a          d=f(a)           d/a          a.grad
        0.1       13     16384.000244     1638.400024    16384.000000   16384.000000
        1.0        9      1024.000000     1024.000000     1024.000000    1024.000000
       -1.0        9    102400.000000  -102400.000000   102400.000000   102400.000000
      100.0        3        16.000000     1600.000000       16.000000       16.000000
     -0.001       19 104857601.562500  -104857.601562 104857600.000000 104857600.000000
        3.7        8       512.000007     1894.400024      512.000000      512.000000
      -42.0        4      3200.000000  -134400.000000     3200.000000     3200.000000

注意一个反直觉的点：a = 0.1 的梯度是 16384，而 a = 100 的梯度只有 16。梯度大不大跟 a 的大小没关系，只跟"这次运行乘了多少次 2"有关 —— 因为斜率（k）是由路径决定的，不是由输入大小决定的。

━━━━━━━━━━━━━━━━━━━━
三、"图是跑出来的，不是写出来的"—— 这是本节真正的知识点

我顺着 grad_fn 往回数了一遍每次运行的图有多深：

        a        循环次数     图深度     反向链的样子
      100.0         3         5      MulBackward0 <- MulBackward0 <- ... <- AccumulateGrad
        1.0         9        11      MulBackward0 <- ...（11 个）
        0.1        13        15      MulBackward0 <- ...（15 个）
      0.001        19        21      MulBackward0 <- ...（21 个）

同一行代码 f，输入不同，图就是不同大小的东西。这就是 PyTorch 的动态图（define-by-run）：

    写代码时：没有图，只有一段普通的 Python 程序
    运行时：  每执行一个张量运算，就把一个节点挂到图上
    求导时：  沿「这一次实际挂出来的那张图」反向走一遍

所以 backward 求的是「这一次运行实际走过的那条路径」的导数，而不是「你写的所有代码」的导数。

这一点是理解全节的关键，也是它比前面几节难的原因：前面你只要看代码就知道图；这里你必须看输入才能知道图。

━━━━━━━━━━━━━━━━━━━━
四、判断语句本身不进图（第二个常见困惑）

很多人以为 if/while 也应该有梯度，或者担心"判断不可导怎么办"。实测一下就很清楚：

    x = 2.0（requires_grad）→ y = x*x = 4.0
    cond = float(y) > 3.0          # ← 这一步把张量变成普通 Python 数，彻底脱离图
    z = y10 if cond else y1
    z.backward()                   # x.grad = 40.0 = 2*x*10

    x = 1.0 → y = 1.0 → 判断 False → z = y → x.grad = 2.0 = 2*x*1

结论：判断语句是图外面的普通布尔值，梯度里根本没有"判断"这一环；梯度只沿着"被选中那条分支里的算术运算"流。

所以「不可导」的不是控制流，而是：
  · 在临界点上发生的行为（比如 |b| 恰好等于 1000，或者 b.sum() 恰好等于 0，斜率在那里是跳变的）；
  · 以及判断所依据的比较本身（它把连续值变成了离散的 True/False）。

实践中 if loss > 某个值: 这种写法不会"切断梯度"，梯度只是不包含"判断"这件事。

━━━━━━━━━━━━━━━━━━━━
五、一个我在实跑中发现的细节（书上没写，但对你做题有影响）

书里的检查是 a.grad == d / a，某次运行打印出 tensor(True)。我跑了 4000 次随机 a 来检验这个等式到底有多"恒等"：

    正 a（k = 2^m，是 2 的整数次幂，float32 能精确表示）:  逐位相等 2028/2028 = 100.0%
    负 a（k = 100·2^m，100 不是 2 的幂，乘法要舍入）    :  逐位相等 1729/1972 =  87.7%
    最大相对误差 = 7.6e-08    （float32 的机器精度上限约 1.19e-07）

怎么解释：a.grad 是把那一串常数乘起来（反向）得到的，d/a 是先乘后除（正向再相除）得到的。数学上是同一个 k，但浮点运算的舍入路径不同：
  · 只乘 2 的时候，乘 2 是"换指数位"，不产生舍入 → 两边逐位相等；
  · 乘 100 的时候会产生舍入，两条路径的最后几位可能不一样。

给你的实用结论：判断梯度对不对，不要用 ==，用 torch.allclose 或看相对误差。这也是 D2L 那些 "x.grad == 2 * x" 的检查在书里能过、你本地偶尔过不去的原因（不是你的环境坏了）。

━━━━━━━━━━━━━━━━━━━━
六、这一节放在教材里的真正用意：深度学习框架的"必答题"

早期 TensorFlow 1.x 是静态图：你要先 tf.placeholder 把图定义好，再 session.run 喂数据。静态图的问题是 —— 图定义的时候还没有数据，那 if / while 怎么写？所以它必须提供 tf.cond / tf.while_loop 这种"把控制流也变成一个算子"的特殊 API，非常难用。

PyTorch 走的是动态图路线：照常写 Python 的 if/for/while，跑到哪就被记到哪。好处是调试体验和写普通程序一样（可以 print、可以打断点、可以 if）；代价是每次迭代都要重新建一次图（有一点固定开销），也解释了为什么后来会有 torch.compile 这类"把动态图抓成静态图再优化"的尝试。

对照到 JAX 上你会看到同样的分叉：普通模式下 Python 的 if 没问题，但一旦 @jit，控制流必须写成 jax.lax.cond / lax.while_loop，否则就会按"第一次运行看到的路径"把图固定下来（想要不同路径就得重新编译）。这就是同一个问题在不同框架里的不同答案 —— 如果你的毕设以后要用 JAX 跑大规模仿真，这个坑一定要提前知道。

━━━━━━━━━━━━━━━━━━━━
七、和你毕设的关系（这一节其实很实用）

你做的轨迹生成里，有两类地方会直接碰到这一节的内容：

  1. 轨迹展开（rollout）：把未来 T 步一步步推出来，就是一段 for 循环 —— 反向传播穿过这个循环，
     图深度随 T 线性增长，显存也跟着涨。这就是序列模型里的 BPTT（时间反向传播），
     以及为什么大家用 truncated BPTT（只回传最近 K 步）。上面第三节那张"图深度随输入变化"的表，
     在轨迹场景里就是"图深度随预测时域变化"。

  2. 运行时决定的结构：比如"迭代几步才收敛"、"选几个模式"、"要不要走某个分支"。
     落到代码里，只要这些数字是 Python 的 int / bool，它们就不参与梯度 —— 这通常是你想要的
     （迭代次数不该有梯度），但如果你其实希望梯度穿过"选择"本身，就必须换成可导的写法
     （softmax 加权、重参数化、Gumbel-softmax）。

把这一节吃透，你以后看到"梯度怎么没了""为什么这步不回传"就有判断依据了。

━━━━━━━━━━━━━━━━━━━━
八、一句话总结

    f(a) 里那个 while 和 if，是「决定走哪条路」的；
    梯度只沿着被选中那条路乘局部导数；
    因为这条路每一步都只是「乘一个常数」，所以 f 最终是 k·a，导数就是 k，
    而 k 顺便也能用 d/a 算出来 —— 这就是 a.grad == d/a 的来历，不是通例，是这个例子的巧合。

    记住真正的那句：图是跑出来的，输入变了，图就变了。
